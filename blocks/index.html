Блоки ​

Блоки — основной строительный элемент макетов в exDoc. Каждый блок представляет собой самостоятельный визуальный компонент с собственным Twig-шаблоном, SCSS-стилями, JavaScript-кодом и набором полей.

Концепция ​

Блок — это переиспользуемый фрагмент страницы. Примеры блоков:

  • Шапка сайта (header)
  • Карточка товара
  • Слайдер баннеров
  • Секция с преимуществами
  • Форма обратной связи
  • Подвал сайта (footer)

Блоки можно вставлять в шаблоны рубрик, в другие блоки и в шаблоны страниц.

Создание блока ​

  1. Перейдите в раздел Блоки в левой панели
  2. Нажмите кнопку Добавить
  3. Заполните основные поля:
    • Название — отображаемое имя блока
    • Хэштег — уникальный идентификатор для использования в шаблонах (например, header, footer, product_card)
    • Категория — группировка блоков для удобства навигации
    • Сортировка — порядок в списке
    • Статус — включен/выключен

Редактирование блока ​

Боковая навигация формы содержит четыре раздела: Поля блока, Макет блока, Макеты полей и Компоненты.

Поля блока ​

Управление кастомными полями блока. Каждое поле хранит данные, которые можно использовать в шаблоне. Подробнее см. Поля.

Макет блока ​

Здесь живёт редактор. Он разделён на вкладки: Шаблон HTML/TWIG, Связи, Языки и Помощь.

Шаблон HTML/TWIG ​

Вкладка содержит три под-вкладки: TWIG, SCSS и JS. Под-вкладка JS появляется, только если у блока включены скрипты.

TWIG — разметка блока.

Пример шаблона:

twig
<div class="hero-banner {{ uniqid }}">
    <h1>{{ fld('title') }}</h1>
    <p>{{ fld('subtitle') }}</p>
    <a href="{{ fld('button_link') }}" class="btn">
        {{ fld('button_text') }}
    </a>
</div>

Доступные функции и свойства в шаблоне блока (объект блока передаётся в контекст Twig, поэтому его методы и свойства вызываются напрямую):

  • fld('hashtag') — значение поля блока
  • fld_list('type') — все поля определённого типа
  • component('hashtag') — вывод компонента блока (с props)
  • include(template_from_string(component('hashtag'))) — вывод компонента с контекстом блока
  • uniqid — уникальный ID блока на странице
  • props — параметры, переданные при вызове блока
  • block_id — ID блока
  • hashtag — хэштег блока
  • lang — мультиязычные данные
  • ex — глобальный объект с функциями exDoc

SCSS — стили блока. Компилируются в CSS на сервере.

scss
.#{$uniqid} {
    padding: 40px 0;
    background: var(--ex-sch-background);

    h1 {
        font-size: 2.5rem;
        color: #fff;
    }

    .btn {
        background: var(--ex-sch-accent);

        &:hover {
            opacity: 0.9;
        }
    }
}

В стилях доступны глобальные SCSS-переменные, миксины и функции, определённые в Быстрых настройках.

JS — код блока, выполняется на фронтенде.

Связи ​

Управление внешними CSS- и JavaScript-ресурсами, которые необходимы блоку:

  • CSS-ссылки — внешние стили (CDN-библиотеки, шрифты)
  • JS-ссылки — внешние скрипты с указанием позиции (header/footer) и атрибутов (async, defer)

Языки ​

Мультиязычный контент блока. Если включена поддержка языков, для каждого языка магазина создаётся свой шаблон. Шаблон выбирается автоматически в зависимости от текущего языка.

Помощь ​

Справка по доступным функциям, полям и компонентам — подсказки можно вставлять в шаблон одним щелчком.

Макеты полей ​

Собственные шаблоны для полей блока. Обычно поле выводится встроенным шаблоном своего типа; здесь этот вывод можно переопределить — задать свою разметку для конкретного поля, не трогая остальные блоки.

Компоненты ​

Компоненты, принадлежащие этому блоку. В отличие от глобальных компонентов из Быстрых настроек, такой компонент существует только внутри своего блока и вызывается в его шаблоне через component('хэштег'). Подробнее см. Компоненты (Блока и рубрики).

Документация блока ​

Описание блока — назначение, примеры использования, параметры — заполняется не в боковой навигации, а кнопкой Документация в шапке формы. Полезно для команды: подсказка остаётся вместе с блоком.

Использование блока в шаблонах ​

Вызов по хэштегу ​

twig
{{ ex.block('header') }}

Вызов по ID ​

twig
{{ ex.block(42) }}

Передача параметров (props) ​

twig
{{ ex.block('product_card', { product: item, show_price: true }) }}

В шаблоне блока параметры доступны через props:

twig
<div class="product-card">
    <h3>{{ props.product.name }}</h3>
    {% if props.show_price %}
        <span class="price">{{ props.product.price }}</span>
    {% endif %}
</div>

Кэширование блоков ​

Если для блока включено кэширование (cache = true), результат рендеринга сохраняется в файловый кэш. Ключ кэша формируется из:

  • ID блока
  • MD5-хэша документа (контекст страницы)
  • Хэша данных фильтрации

Очистка кэша ​

Работают два уровня, и путать их не стоит.

Кэш самого блока очищается автоматически при каждом сохранении блока в админ-панели. Ничего включать не нужно: записи этого блока удаляются, и следующий посетитель получит свежий результат.

Системный кэш — общий кэш всего сайта — по умолчанию не трогается. Его очистку включает переключатель Очищать кэш после сохранения в настройках блока: после успешного сохранения exDoc дополнительно сбрасывает системный кэш целиком и сообщает об этом уведомлением.

Переключатель нужен, когда правка блока влияет не только на него: блок используется в шаблоне, участвует в общей вёрстке или его стили попадают в общий CSS. В обычной работе он не нужен — очистки кэша самого блока достаточно, а полный сброс заставляет сайт пересобирать всё заново.

Такой же переключатель есть у рубрики и работает точно так же.

Пресеты блоков ​

Можно загружать готовые блоки из библиотеки пресетов:

  1. Откройте модальное окно Пресеты блоков через верхнее меню
  2. Выберите пресет из доступных
  3. Импортируйте его в проект
